# SciAgent-Bench: technical report

Generated by `sciagent report` (v0.2.0) on 2026-10-13 from: `results/cpu`. Every number below is read from those result files.

## Summary

SciAgent-Bench evaluates planners that decide which simulations to run, and at which fidelity, under a fixed compute budget. Three scientific tasks with verified reference optima are used: a chemical batch reactor (exact optimum; cheap solvers are biased), a 2-D heat-conduction design problem (grid fidelity) and a MIMO energy-efficiency problem (noisy Monte-Carlo fidelity). The score is the regret of the design each planner would report. Key results:

- Classical planners, budget 120, **reactor**: lowest mean regret by `scripted-mf` (0.0102); significantly better than `random`, `bo` (Holm p < 0.05); not significantly different from `sh`.
- Classical planners, budget 120, **heat**: lowest mean regret by `scripted-mf` (0.0371); significantly better than `random`, `bo` (Holm p < 0.05); not significantly different from `sh`.
- Classical planners, budget 120, **mimo**: lowest mean regret by `scripted-mf` (0.072); significantly better than `random`, `bo`, `sh` (Holm p < 0.05).
- Classical planners, budget 300, **reactor**: lowest mean regret by `scripted-mf` (0.00299); significantly better than `random`, `bo`, `sh` (Holm p < 0.05).
- Classical planners, budget 300, **heat**: lowest mean regret by `scripted-mf` (0.0119); significantly better than `random`, `sh`, `bo` (Holm p < 0.05).
- Classical planners, budget 300, **mimo**: lowest mean regret by `bo` (0.00665); significantly better than `random`, `sh`, `scripted-mf` (Holm p < 0.05).

## 3. Methods

**Planners.** `random`: uniform sampling at the top fidelity. `sh`: budget-aware successive halving across fidelities (eta = 3). `bo`: Gaussian-process Bayesian optimisation (Matern 5/2, expected improvement, batched by kriging believer) at the top fidelity. `scripted-mf`: a hand-written explore-refine-confirm multi-fidelity policy run through the full LLM-agent code path with a deterministic mock model (a baseline, not an LLM). LLM planners receive the researcher's goal, the simulator card, budget state, the run history and optional tool outputs (GP suggestions), and must return a JSON plan.

**Budget enforcement.** Planners only propose. A deterministic guard enforces bounds, fidelity names, batch size and the remaining budget through a reserve/commit ledger; property-based tests check that no proposal can overspend. LLM spend is capped before each call using a worst-case estimate.

**Metric.** Regret = reference optimum minus the noise-free objective of the reported incumbent (the best result at the highest fidelity evaluated). AUC = mean log10 regret over the budget (anytime performance).

**Statistics.** Seeded bootstrap 95% CIs of the mean (10,000 resamples); paired Wilcoxon signed-rank tests over seeds against the best planner per task with Holm correction; success = regret below a task tolerance.

**Reproducibility.** Seeds derive from (study seed, run index); every run records its spec, environment and a results digest. LLM calls are recorded to cassettes so that LLM-driven campaigns replay exactly; interrupted studies resume by fast-forwarding recorded runs.

## 6. Limitations

- The three tasks are inexpensive stand-ins chosen so that the benchmark and its statistics run in CI; real lab codes plug in through the simulator template, and conclusions about planners may not transfer to them.
- `heat` and `mimo` references are best-known values with the verification above, not proofs of global optimality; `reactor` is exact.
- Regret is measured in each task's own units, so values are compared within a task, not across tasks.
- LLM results depend on the model version, serving stack and prompt; they are reproducible from the recorded cassettes, not from re-querying the model.
- Paired tests match planners by seed. Planners share a seed's random stream only partly, so pairs are weakly matched: the tests remain valid but have less power than a fully matched design.
